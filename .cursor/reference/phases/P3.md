# P3 — API backend

**Goal:** the real API, built **endpoint by endpoint**, matching the P2 contracts. UI still on mocks.

### Subs

- [ ] P3.1 **Bootstrap** — router, request/response helpers, `jsonSuccess()` / `jsonError()` (one consistent shape), error handler, CORS from env, request logging
- [ ] P3.2 **DB access** — `Database::query()`/`execute()` with **prepared statements only**; transaction helper
- [ ] P3.3 **Migrations applied** on local DB; seeds usable
- [ ] P3.4 **Auth** — `register()`, `login()`, `logout()`, `refresh()`/session, `me()`, password hashing/verify, token/session issue + expiry
- [ ] P3.5 **Middleware** — `authenticate()`, `requireRole(...roles)`, ownership check `canAccess(user, resource)`, rate limit on auth
- [ ] P3.6 **Validation layer** — server validators per endpoint as named functions; **every write validated server-side**; errors map to field names matching the UI form fields
- [ ] P3.7 **Endpoints, one by one** — for each row in the endpoint inventory, a Function Spec covering: route, handler function, service function(s), repository function(s), validator, authz, response shape, error cases, tests. Typical set per entity: `list` (filter/sort/paginate), `get`, `create`, `update`, `delete` (soft-delete if norm), plus concept-specific actions
- [ ] P3.8 **Special endpoints** if in concept: file upload (type/size/path checks), payments, notifications, exports
- [ ] P3.9 **Per-endpoint tests** — happy · validation fail (422 with field errors) · unauthenticated (401) · forbidden (403) · not found (404)
- [ ] P3.10 **API smoke run** — Postman-style/manual collection covering every endpoint; saved in repo
- [ ] P3.11 **Contract list** — final routes + payloads vs P2 contracts; diffs noted for P4

### Exit (P3 → P4)

Run **Phase exit gate**. Verify: every inventory endpoint `done` with tests; authz enforced server-side (not UI-only); prepared statements everywhere; contract diffs listed; UI still on mocks is OK.
